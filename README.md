# gform_ontime — 구글 폼 "서버 시각 기준 정각" 제출

구글 폼 응답 **1건**이 구글 서버 시계로 목표 시각(예: `22:00:00.000`) **직후**에 찍히도록 보내는 도구입니다.
목표보다 **이르게 찍히는 일이 없도록** 설계했고(선착순에서 이른 제출은 보통 무효), 그 범위 안에서 최대한 빨리 도착시킵니다.

| 파일 | 용도 |
|---|---|
| `gform_ontime.py` | 본체. 파이썬 3.8 이상, 추가 설치 없음 |
| `browser/console_snippet.js` | 설치 없이 크롬 개발자도구 콘솔에 붙여 넣는 방식 (로그인 필요한 폼 포함) |
| `tests/` | 로컬 모의 서버로 돌리는 자동 테스트 (구글에 아무것도 보내지 않음) |

---

## 1. 원리 — 왜 "정각"을 맞출 수 있나

**① 구글이 자기 시계를 알려 줍니다.** 두 가지 경로로 읽습니다.

- `docs.google.com/generate_204` 응답의 `Date` 헤더: 초 단위(내림)입니다. 요청을 "초가 바뀌는 순간"에 걸치도록 겨냥해 여러 번 보내면
  (이분 탐색) 서버 시계를 왕복 지연 정도의 오차로 좁힐 수 있습니다. 네이비즘류 서버시간 사이트가 쓰는 헤더와 같지만, 경계 탐색으로 1초 해상도의 한계를 넘습니다.
- 폼 페이지 HTML 안의 `"server_time_ms": 1794804540448`: 폼 서버(응답에 타임스탬프를 찍는 쪽)의 시계가 **밀리초**로 들어 있습니다.

**② 측정값은 "추정"이 아니라 "부등식"으로 씁니다.** PC의 단조 시계 `t`와 서버 시계의 차이를 θ라 하면(`서버시각 = t + θ`),
응답 하나마다 다음이 성립합니다.

```
θ ≥ (서버가 알려준 시각) − (내가 응답을 받은 시각)      ← 서버가 시계를 읽은 건 내가 받기 전이므로
θ < (서버가 알려준 시각) − (내가 요청을 보낸 시각) + 해상도
```

여러 번 측정해 가장 큰 하한을 `θ_lo`라 하면, **내가 `t`에 보낸 요청은 서버 시각 `t + θ_lo` 이전에는 PC를 떠날 수조차 없습니다.**

**③ safe 모드(기본)** 는 요청 전체를 한 번의 쓰기로 `t = T − θ_lo + 10ms`에 내보냅니다.
네트워크와 구글 내부 처리는 시간을 **더할 뿐**이므로, 기록 시각은 반드시 목표 `T` 이후입니다.
얼마나 뒤인지는 "PC→구글 편도 지연 + 구글 폼 서버의 처리 시간"이고, 보통 같은 초 안(수십~200 ms대)입니다.

**④ 그 외 안전장치**

- PC의 벽시계(윈도우 시계)는 전혀 쓰지 않습니다. 몇 초 틀려 있어도 상관없습니다.
- 제출은 정확히 1회. 응답을 못 받은 애매한 경우에도 자동 재전송하지 않습니다(중복 기록 방지).
- `/formResponse` 주소에는 그 한 번의 제출 외에 어떤 요청도 보내지 않습니다.
- 요청을 미리 일부만 보내 두는 기법(last-byte sync)은 쓰지 않습니다. 서버가 "요청 시작 시각"으로 찍는다면 오히려 이르게 찍힐 수 있어서입니다.

## 2. 빠른 시작

파이썬이 없다면 <https://www.python.org/downloads/> 에서 설치합니다(윈도우는 설치 화면의 "Add python.exe to PATH" 체크).
이 저장소를 내려받아 그 폴더에서 터미널(윈도우: PowerShell)을 엽니다. 윈도우에서 `python`이 안 되면 `py`로 바꿔 입력하세요.

```bash
# 1) 폼 확인: 질문, 보기, 열려 있는지
python gform_ontime.py inspect "폼주소"

# 2) 구글 서버 시계와 내 PC 시계 차이, 왕복 지연 보기 (읽기 전용)
python gform_ontime.py clock "폼주소"

# 3) 리허설: 제출 없이 전 과정을 수행하고, 발사 순간에 '폼 페이지 읽기' 요청을 보내 어디에 떨어지는지 확인
python gform_ontime.py rehearse "폼주소"

# 4) 실제 제출 (목표 시각은 날짜 + 24시간제로)
python gform_ontime.py fire "폼주소" --at "2026-11-23 22:00:00" --answer "학년=2" --answer "이름=홍길동"
```

- `--at`은 **날짜와 24시간제 시각을 모두** 적습니다. 오전 10시는 `10:00:00`, 밤 10시는 `22:00:00`입니다. PC의 시간대로 해석하며, 실행하면 요일·UTC 환산·남은 시간을 다시 보여 주니 꼭 확인하세요.
- `--answer "질문제목=값"`을 질문마다 적습니다. 생략한 질문은 실행 중에 물어봅니다. 객관식 값은 보기와 정확히 같아야 하며, 다르면 보내기 전에 거절합니다.
- 실행 후 내용을 확인하고 `y`를 누르면 카운트다운이 시작됩니다. 목표 몇 분 전에 실행해 두면 됩니다(몇 시간 전이어도 됩니다).

### 당일 체크리스트

1. 목표 5~10분 전에 `fire` 실행. 유선 랜 > 5GHz 와이파이 > 그 외. VPN·프록시는 끄기.
2. 노트북은 전원 연결, 무거운 프로그램 종료. 터미널 창은 그대로 두기(절전·덮개 닫기 금지).
3. 그 전에 같은 자리에서 `rehearse`를 한 번 돌려 "목표 대비 +몇 ms"가 나오는지 확인.
4. 만약을 위해 브라우저에 폼을 열어 답을 채워 둔 탭을 하나 준비(도구가 실패하면 직접 제출).
5. 결과가 `[불명]`이면 **다시 보내지 말고** 주최 측에 확인.

## 3. 결과 읽는 법

```
[성공] 응답이 기록되었습니다.
  요청이 PC를 떠난 시각(서버 기준) : 22:00:00.010 ~ 22:00:00.018   (목표 +10.0 ms ~ +18.2 ms)
  제출 확인 페이지의 서버시각      : 22:00:00.143   (목표 +143.0 ms)
  => 기록 시각은 22:00:00.010 ~ 22:00:00.143 사이입니다.
```

- 응답자는 자기 타임스탬프를 직접 볼 수 없습니다. 대신 "요청이 떠난 시각(하한)"과 "확인 페이지가 만들어진 시각(상한)" 사이로 좁혀 보여 주고, 같은 내용을 `gform_ontime_fire_*.json`/`.html`로 저장합니다(증빙용).
- **응답 시트의 기본 표시는 초 단위로 반올림**됩니다. 실제 값이 `22:00:00.000~.499`이면 `22:00:00`으로, `.500~.999`이면 `22:00:01`로 보입니다(실제 값은 밀리초까지 저장되어 있고, 셀 서식을 `hh:mm:ss.000`으로 바꾸면 보입니다). 반대로 `21:59:59.5~.9`에 찍힌 응답도 기본 표시로는 `22:00:00`으로 보이지만, 실제로는 정각 이전이므로 이 도구는 그 구간을 겨냥하지 않습니다.
- 가까운 시각(약 0.1초 이내)에 들어온 응답들의 **시트 행 순서는 타임스탬프 순서와 다를 수 있습니다**(공개 응답 시트 분석 결과). 순위는 주최 측이 무엇을 기준으로 보는지에 달려 있습니다.

## 4. 폼이 닫혀 있다가 정각에 열리는 경우

주최 측이 폼을 닫아 두었다가 시각에 맞춰 여는 방식이면 "정각에 찍히게"는 불가능하고 "열리자마자"가 목표가 됩니다.
`fire`는 이 상황을 자동으로 처리합니다.

- 시작할 때 닫혀 있으면: 질문을 읽을 수 없으므로 `--answer`로 답을 모두 지정해야 합니다. 열릴 때까지 0.3초 간격으로 확인하다가, 열리면 질문과 답을 대조한 뒤 즉시 제출합니다(단, 목표 시각 이전에는 보내지 않습니다).
- 열려 있다가 발사 직전에 닫힌 경우에도 같은 방식으로 넘어갑니다.
- 기다리지 않으려면 `--no-wait-open`, 확인 간격은 `--poll-ms`(최소 200), 최대 대기는 `--wait-max`(초).

## 5. 더 정밀하게: 본인 폼으로 보정 (선택)

실제 폼에는 연습 제출을 할 수 없으므로, **본인이 만든 같은 구조의 연습용 폼**으로 "보낸 뒤 얼마 만에 찍히는지"를 잽니다.

1. 구글 폼에서 같은 질문(학년/이름)으로 연습용 폼을 만들고, [응답] 탭 → **Sheets에 연결**.
2. 그 시트를 [공유] → "링크가 있는 모든 사용자 — 뷰어"로 설정.
3. 실행:

```bash
python gform_ontime.py calibrate "연습용폼주소" --sheet "응답시트주소" --answer "학년=1"
```

연습용 폼에 6건을 실제 방식 그대로 제출하고, 시트에서 밀리초 타임스탬프를 읽어 표로 보여 줍니다.

- "safe 모드는 한 번도 목표보다 이르지 않았습니다"가 나오면 이 문서의 가정이 여러분 환경에서 확인된 것입니다.
- 결과는 `gform_ontime_calibration.json`에 저장되고, 이후 `fire`가 예상 기록 시각을 더 정확히 알려 줍니다.
- **fast 모드**(`fire --mode fast`): 보정에서 잰 "PC 출발→기록" 최소 지연에서 여유 30 ms를 뺀 만큼 **일찍** 내보내 목표+30 ms 부근을 노립니다. 더 빨리 찍히지만 **"절대 이르지 않음" 보장이 없습니다**(구글 쪽 처리가 보정 때보다 빠르면 정각 이전으로 찍힐 수 있음). 보정 없이는 실행되지 않습니다.

시트에서 직접 눈으로 확인하려면 타임스탬프 열의 서식을 `yyyy-mm-dd hh:mm:ss.000`으로 바꾸면 됩니다.

## 6. 브라우저 콘솔 방식 (설치 없이)

`browser/console_snippet.js`는 같은 원리를 브라우저 안에서 수행합니다. 구글 로그인이 필요한 폼, 파이썬을 설치하기 어려운 PC에서 씁니다.

1. 크롬에서 폼을 열고 답을 채웁니다(폼의 제출 버튼은 누르지 않음).
2. `F12` → Console. 파일 맨 위 설정(`at`, `dryRun`, 필요하면 `answers`)을 고친 뒤 전체를 붙여 넣고 Enter. 처음 붙여 넣을 때 크롬이 `allow pasting` 입력을 요구합니다.
3. 먼저 `dryRun: true`(기본)로 리허설하고, 실제 제출은 `dryRun: false`로 다시 실행합니다.
4. 결과가 나올 때까지 그 탭을 화면에 보이는 상태로 둡니다(최소화·다른 탭 전환 금지).

자세한 사용법은 파일 머리말에 있습니다.

## 7. 보장하는 것과 못 하는 것

| | |
|---|---|
| 보장 (safe 모드) | 요청이 구글 서버 시각으로 목표+10 ms 이전에 PC를 떠나지 않음 → 목표 이전에 찍히지 않음 |
| 보장 | 제출은 1건. 애매하면 재전송하지 않고 알림 |
| 보장 못 함 | 정확히 `.000`에 찍히는 것. 구글 폼 서버의 처리 시간(수십~수백 ms, 매번 다름)은 밖에서 제어할 수 없음 |
| 보장 못 함 | 순위. 다른 사람의 제출과 주최 측의 판정 방식에 달려 있음 |
| 확인 필요 | 주최 측 공지의 정확한 날짜와 시각(오전/오후), 그리고 자동 제출을 금지하는지 여부 |

전제 조건: "서버가 알려주는 시각은 그 순간 서버 시계의 내림값이다", "응답 타임스탬프는 요청이 완전히 도착한 뒤에 찍힌다", "구글 앞단 서버와 폼 서버의 시계가 (10 ms 여유 안에서) 같다".
앞의 둘은 실제 서버를 읽기 전용으로 수백 회 측정해 모순이 없음을 확인했고, 세 가지 모두 5절의 보정으로 본인 환경에서 직접 검증할 수 있습니다.
도구는 측정값끼리 모순되면(절전에서 깨어남 등) 과거 측정을 버리고 다시 좁히며, 그동안은 더 늦게(안전한 쪽으로) 보냅니다.

지원하지 않는 폼: 파일 업로드·그리드 질문, 구글 로그인이 필요한 폼(→ 브라우저 방식), 제출 시 캡차를 쓰는 폼(경고 후 시도).

## 8. 명령 요약

| 명령 | 설명 |
|---|---|
| `inspect URL` | 질문·보기·필수 여부·상태 |
| `clock URL [--seconds 20]` | 구글 서버 시각, PC 시계와의 차이, 왕복 지연 |
| `rehearse URL [--count 3] [--at ...]` | 제출 없는 리허설(읽기 요청만 보냄) |
| `fire URL --at "YYYY-MM-DD HH:MM:SS" --answer "질문=값" ...` | 실제 제출 |
| `calibrate 내폼URL --sheet 시트URL` | 본인 폼으로 실제 기록 시각 측정 |
| `selftest` | 이 PC의 타이머 정밀도 점검 |

`fire` 주요 옵션: `--mode safe|fast`, `--guard-ms 10`(safe의 여유), `--margin-ms 30`(fast의 여유), `--utc-offset +09:00`(시간대 직접 지정),
`--on-unknown stop|retry`(응답을 못 받았을 때. 기본 stop. retry는 중복 기록 위험을 감수), `--yes`(확인 생략).

종료 코드: 0 기록됨 · 2 취소/입력 오류 · 3 폼 닫힘 · 4 거절됨 · 5 불명/전송 실패.

## 9. 테스트

```bash
python -m unittest discover -s tests -v            # 약 3분. 로컬 모의 서버만 사용
GFORM_SLOW_TESTS=1 python -m unittest discover -s tests -v   # 100초 전체 카운트다운 포함
node tests/browser/run_snippet_e2e.js              # 브라우저 스니펫 (Node + Playwright 필요)
```

모의 서버(`tests/mock_forms_server.py`)는 서버 시계를 PC와 다르게 두고 네트워크·서버 지연을 흉내 내므로,
"서버 시계에 실제로 맞춰야만" 통과합니다. 직접 띄워서 연습할 수도 있습니다: `python tests/mock_forms_server.py`.
